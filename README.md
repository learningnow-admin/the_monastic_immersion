# The Monastic Immersion

A one-page web app for a small group that consumes cultural artifacts together.
Each session gathers artifacts: up to two per member, fifteen minutes in all,
with no ceiling on the session. Three are enough to set a day, and anything
past three is a bonus. Days can be proposed and voted on from the start.
Whoever clicks first hosts (default: Nina's house); meet (7:30 pm, always),
mark it done, and the next session begins with a day four weeks on already
proposed.

A member can sit a session out any time before the session is done: their
artifacts are withdrawn, hosting is handed back, and they leave the vote marks
so nobody waits on them. Rejoining restores the allowance and any earlier
votes. The quorum stays at three and bends down only when the members still
in can't reach it. Absences are per session; everyone is back in when the
next begins.

## Guests

Guests are a written rule, not a feature. Any member may bring one guest to a
session. The guest gets their own two artifacts and fifteen minutes, recorded
under the inviting member's link with the guest's name in the guest box (all
of one member's guest artifacts in a session must carry the same name). The
inviter answers for the guest on days; guests don't vote.

A guest who wants to keep coming becomes a member: add a row and send them
the link. After that neither the inviter nor the new member may invite anyone
else, which caps the group at ten.

```sh
npx wrangler d1 execute tmi --remote --command "INSERT INTO members (name, token) VALUES ('Sam', lower(hex(randomblob(9))))"
```

## Stack

- **Squint** (`src/worker.cljs`) — Clojure syntax compiled to a plain JS module.
  The compiled `src/worker.mjs` is gitignored; `npm run build` regenerates it.
- **Cloudflare Worker** (`src/index.mjs` entry) serving server-rendered HTML,
  plain form POSTs, zero client-side JavaScript.
- **D1** (SQLite) for storage; schema in `migrations/`.

## Identity & security

Each member has a personal secret link: `/m/<token>`. The server resolves who
is acting from the token on every request — form fields are never trusted for
identity, so members cannot act as each other. The bare root URL shows nothing.
Members are pseudonymous (Nina, Kai, Ada, Otto, Cass), one link each; tokens
are random 18-hex strings generated by the migrations.

List everyone's links:

```sh
npx wrangler d1 execute tmi --remote --command "SELECT name, token FROM members"
```

If someone's link leaks, reissue it:

```sh
npx wrangler d1 execute tmi --remote --command "UPDATE members SET token = lower(hex(randomblob(9))) WHERE name = 'Kai'"
```

## Local development

```sh
npm install
npm run db:local     # apply migrations to the local sqlite
npm run dev          # build + wrangler dev on http://localhost:8787
```

Get local test links with the `--local` variant of the token query above.
To reset local data: delete `.wrangler/state` and run `npm run db:local` again.

## Deploying (first time)

1. `npx wrangler login`
2. `npx wrangler d1 create tmi` — copy the returned `database_id` into
   `wrangler.toml`.
3. `npm run db:remote`
4. `npm run deploy` — the URL is printed at the end.
5. Run the token query above and send each member their personal link.

After that, updates are just `npm run deploy`.

Tweakables in `src/worker.cljs`: `meeting-time`, `meeting-place` (the default
when nobody offers to host), `per-person` (artifacts each member, and each
guest, may add per session), `quorum` (artifacts needed to lock a day),
`artifact-types`, `rules`, `procedure`, `guests`, `influences`. Renaming a
member touches five tables:

```sh
npx wrangler d1 execute tmi --remote --command "UPDATE members SET name='NewName' WHERE name='Kai'; UPDATE artifacts SET member='NewName' WHERE member='Kai'; UPDATE votes SET member='NewName' WHERE member='Kai'; UPDATE absences SET member='NewName' WHERE member='Kai'; UPDATE sessions SET host='NewName' WHERE host='Kai'"
```
